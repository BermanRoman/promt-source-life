# Локальный CLI компонентов

Python 3.9+, только стандартная библиотека; скрипт читает данные, без сети, checkout, установки зависимостей и записи в репозитории.

`dependencies.json` содержит шесть маршрутов, точный commit и SHA-256 каждого разрешённого файла; рабочая цепочка объявлена явно, сканирования чужих архивов и пользовательских записей нет.

```sh
python3 -B scripts/components.py check --route relationships
python3 -B scripts/components.py check --route job-search --route hiring --repos-root /path/to/local/repos
python3 -B scripts/components.py index relationships-methodology.md --route relationships
python3 -B scripts/components.py extract relationships-methodology.md --route relationships --heading 'Блок 1. Сценарий А: партнёра нет'
python3 -B scripts/components.py index behavior-methodology.md --local
python3 -B scripts/components.py extract core/orchestration.md --local --heading 'Точный заголовок из index'
```

Сначала получи `index`: подписи в примерах `extract` показывают синтаксис, а точный существующий заголовок нужно взять из индекса текущего файла.

`--repos-root` — родитель соседних локальных клонов, не конкретный клон; по умолчанию это родитель данного репозитория независимо от cwd.

`check` требует хотя бы один `--route`, проверяет только выбранные репозитории и печатает `ROUTE: ok` после успеха всего запроса.

Доступны `core`, `relationships`, `job-search`, `hiring`, `audience`, `sales-training`; отсутствующая невыбранная ветка не блокирует работу.

`index` и `extract` для внешнего файла требуют ровно один маршрут; файл должен быть объявлен именно в нём.

Проверяется вся объявленная рабочая цепочка выбранной ветки, поэтому отсутствие нужного профиля или инструмента не маскируется успешным чтением роутера.

`--local` разрешает только `master-prompt.md`, `behavior-methodology.md`, `style-core.md`, `spin-core.md`, `addiction-questions.md`, `diary.md` и Markdown под `core/` и `methods/` этого репозитория.

Здесь `diary.md` — библиотечный шаблон, а пользовательские дневники и runs не разрешены; локальные чтения показывают текущие байты без утверждения о внешнем Git-пине.

Абсолютные пути, `..`, скрытые/приватные каталоги, симлинки в пути и выход из корня отклоняются; локальный режим не является универсальным читателем личных файлов.

`--heading` повторяется для нескольких точных ATX-заголовков, без символов `#`; раздел включает дочерние заголовки до следующего заголовка того же или меньшего уровня.

Заголовки внутри fenced code игнорируются; отсутствующий, неоднозначный или повторный селектор — ошибка; пересекающиеся диапазоны объединяются и выводятся в порядке исходника.

Без `--heading` `extract` возвращает полный файл; `index` выдаёт заголовки и их уровни.

SHA-256 исходных байтов, SHA-256 выбранного UTF-8 текста и его длина выводятся в stderr, содержимое — в stdout.

При ошибке код 2 и пустой stdout: скрипт сначала полностью готовит результат, затем выводит его; постоянный файл назначения не создаётся.

Перенаправление оболочки `>` само по себе может обнулить прежний файл до запуска скрипта; для сохранения результата используй временный файл и переименование только при коде 0.

## Проверка и обновление пинов

Проверка требует точного HEAD и Git top level без симлинков, regular-file объекта в закреплённом commit, совпадения фактических байтов с объектом и SHA-256.

Git вызывается с `--no-replace-objects`, а байты читаются напрямую: `git replace`, `assume-unchanged`, `skip-worktree` и чистый `git status` не подменяют проверку.

Равенство SHA контрактов найма/поиска проверяется в manifest всегда; каждый выбранный клон сверяется с собственным пином, а `check` обоих маршрутов подтверждает оба локальных снимка.

Обновление внешнего компонента — отдельная осознанная работа: прочитать дифф методики и контрактов, проверить совместимость адаптера, изменить revision и SHA файлов вместе, затем прогнать затронутые проверки.

Если меняется объявленная цепочка файлов, синхронно обнови `REQUIRED_FILES` в скрипте: схема намеренно отклоняет неполный профиль, даже если его короткая точка входа доступна.

CLI не доказывает истинность профессиональных фактов, актуальность сайтов/разрешения и независимость содержательной проверки, не запускает саму ветку и не переносит приватные сведения между сторонами.

Пины не являются подписью: доверие к содержанию manifest и локальному коду остаётся условием проверки; одновременную злонамеренную подмену обоих скрипт не предотвращает.

```sh
python3 -B -m unittest discover -s tests -p test_components.py -v
```

Тесты создают временные синтетические Git-репозитории, проверяют байты/HEAD/replace, скрытые правки, отсутствующие файлы/маршруты/профили, равенство контрактов, симлинки/корень, точные секции и пустой stdout при ошибке.
