# Подготовка и обновление

## Найти существующее

Восстанови текущий проект, инструкции, личный каталог и папку Drive из его состояния; уже работающую схему не перенастраивай без поручения.

Библиотека и личный дневник — разные каталоги; данные не публикуются вместе с исходниками.

Загрузка репозитория не запускает опрос и не разрешает доступ к чужим аккаунтам.

## Подключить библиотеку

Начни с [master-prompt.md](../master-prompt.md), затем прочитай указанные обязательные границы и только нужные полные разделы.

В файловой среде положи библиотеку в доступный каталог; в среде с загрузкой документов сохрани структуру или однозначное соответствие имён, чтобы все ссылки маршрута разрешались.

Модель, тариф, приложение и подключения остаются выбранными пользователем.

Управленческий аппарат обязателен в основном маршруте; внешние ветки подключаются по [адаптеру](../integrations/components.md), не все сразу.

```sh
python3 scripts/components.py check --route core
python3 scripts/components.py check --route relationships
python3 scripts/components.py index behavior-methodology.md --local
```

Точные CLI и порядок подготовки отсутствующего клона — [памятка компонентов](components-cli.md).

Существующие несовместимые клоны сохраняются; совместимый набор можно подготовить в отдельном каталоге и указать его явно.

Не загружай случайные файлы из main поверх закреплённых версий; обновление зависимости требует проверки совместимости и байтов.

## Настроить двойное хранение

Канон — [core/storage.md](../core/storage.md); локальные команды и ограничения — [docs/store-cli.md](store-cli.md).

Для нового приватного локального каталога:

```sh
python3 scripts/store.py --root /absolute/private/source-life init
```

Каталог выбирает пользователь/действующий проект; пример не является общей папкой всех дневников.

Drive остаётся полноценным предусмотренным вариантом второй реплики: проверь доступный коннектор, выбранный аккаунт/папку и разрешённые действия.

Права на чтение не означают права на запись, удаление или обмен ссылкой; чтение/создание/обновление выдаются по нужной задаче, доступ всем и лишнее удаление не требуются.

Проверь операции на отдельном неперсональном документе в разрешённом месте до записи чувствительных данных; создание и обновление сверяй повторным чтением.

Если дневник уже существует в Drive, сначала восстанови его идентификаторы и содержимое, затем согласуй локальную реплику; не создавай рядом второй дневник с тем же именем.

Если одновременно существуют две версии, проведи сверку по общей базе и разреши конфликт, а не выбирай последнюю по времени.

При недоступном Drive локальная очередь сохраняет долг; при недоступной локальной стороне действуют ограничения облачного продолжения из storage, без фиктивного статуса «обе копии».

Без доступного подключения программа из репозитория не выполняет живую синхронизацию сама: она хранит очередь и проверяет данные результата, а запись делает разрешённый инструмент среды.

## Обновить

Проверь origin, статус рабочего дерева, собственные изменения и текущую версию; не сбрасывай изменения и не переключай действующие клоны зависимостей автоматически.

Обновляй библиотеку и манифест отдельно от личного хранилища; миграция данных не следует из обновления промптов.

Для совместимой чистой ветки используй обычное fast-forward обновление по текущему поручению; при расхождении сохрани изменения и разберись с причиной.

После изменения маршрута, версии источника или входных фактов обнови затронутые проверки, не начинай все анкеты заново.

```sh
python3 -m unittest discover -s tests -v
git diff --check
```

Локальные тесты с макетом Drive проверяют протокол и сохранность данных, а не доступность настоящего коннектора; фактическая работа обеих реплик требует отдельного подтверждения в среде пользователя.
